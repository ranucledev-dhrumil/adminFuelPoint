# FuelPoint Admin — Frontend

Admin dashboard for a petrol-pump customer-discount system. It is a **pure client-side React SPA** (no SSR, no server code). This folder is the frontend only; the Node.js + PostgreSQL backend lives in `../backend` and is not built yet, so all data is currently mock data.

## Stack

| Area | Choice |
|---|---|
| Language / UI | TypeScript, React 19 |
| Build tool | Vite 8 |
| Routing | TanStack Router (file-based routes in `src/routes`, code-split per route) |
| Data fetching | TanStack Query (client is created in `src/router.tsx`; not used for data yet) |
| Styling | Tailwind CSS v4, shadcn/ui (Radix primitives) |
| Forms / validation | react-hook-form, zod |
| Charts | Recharts |
| Notifications | sonner (toasts) |
| Tooling | ESLint, Prettier (100 columns), npm |

## Getting started

Requires Node.js 22 and npm.

```bash
npm install
npm run dev        # http://localhost:5173
```

| Script | What it does |
|---|---|
| `npm run dev` | Vite dev server |
| `npm run build` | Production build into `dist/` |
| `npm run preview` | Serve the production build locally |
| `npm run typecheck` | `tsc --noEmit` (see Known issues) |
| `npm run lint` | ESLint |
| `npm run format` | Prettier |

## Routes

| Path | Page |
|---|---|
| `/` | Sign in |
| `/dashboard` | Overview and charts |
| `/workers` | Worker list / create / edit |
| `/customers` | Customer list / create / edit, group assignment |
| `/groups` | Discount groups |
| `/reports` | Reports |
| `/notifications` | Notifications |
| `/profile` | Admin profile |
| `/search?q=` | Global search |

Everything except `/` sits under the `_admin` layout, which redirects to `/` when not signed in.

## How data and auth work today (mock)

- **Auth is a placeholder.** Any email plus a password of 4+ characters signs in. A flag in `sessionStorage` (`fuelpoint-admin-authed`) keeps the session across refreshes. There is no token and no real security.
- **All data is mock.** `services/mockData.ts` generates fixed data; `lib/admin-store.tsx` copies it into React state, and create/edit/delete actions change only that in-memory state. Refreshing the page resets it.
- **The integration seam for the backend is `services/adminService.ts`.** Its own comment says to replace the function bodies with real HTTP calls. Note that the store currently reads these synchronously (`getCustomers(): Customer[]`), so moving to a real API means making them async (for example with TanStack Query) and updating the store and pages accordingly.
- UI preferences are stored in `localStorage`: theme (`fuelpoint-theme`) and sidebar state (`fuelpoint-sidebar-collapsed`).

## Notes

- **shadcn/ui components:** `src/components/ui` includes components no page uses yet. They are kept on purpose for future use.
- **Path alias:** `@/` maps to `src/`.
- **Deployment:** the build is static files in `dist/`. Any static host works, but it must rewrite unknown paths to `/index.html` so deep links such as `/customers` work on refresh. No hosting target has been chosen or configured yet.

## Known issues

- `npm run typecheck` reports 9 type errors that existed before the SPA migration: 2 in `components/admin/AdminShell.tsx` and 7 in `routes/_admin.search.tsx` (for example, the search page passes a `description` prop that `PageHeader` does not accept). `vite build` does not type-check, so the build still succeeds.
